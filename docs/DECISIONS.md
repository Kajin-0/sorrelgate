# Sorrelgate — Decision register

**Policy:** Never silently reverse decisions. Append dated records with rationale, competing alternatives and outcome.

## ADR-017 — 2026-11-21T06:50:55.923Z — Frozen, durable creation intent instead of cross-database atomicity
**Accepted design (CI pending):** A Sorrelgate transaction and its complete `ChecklistSeedPlan` are written in one `transactions.sqlite` SQLite transaction before any `documents.sqlite` write. This `transaction_checklist_intents` outbox contains the exact selected office name/ID, workflow, template revision and immutable task metadata. A separate local `documents.sqlite` transaction inserts task rows and provenance atomically. Recovery retries unfinished intents on reopen; a repeated seed verifies source identity without changing old tasks or completion/document links; acknowledge deletes the intent only after verification. A missing/mismatched source with manually entered tasks causes an explicit conflict and leaves the intent for review. **Rationale:** attaching databases with WAL does not provide a dependable cross-file atomic commit; a durable replay protocol preserves attribution without a wholesale schema rewrite. **Tradeoffs:** new transactions are recoverable across both crash windows, but transactions created by older versions without a durable intent cannot reconstruct their lost office choice. Legacy manual starter loading remains available; do not silently claim those are office-specific or legally mandatory. Error/permission/disk and actual UI pilot tests remain outstanding.


## ADR-016 — 2026-11-21T06:35:23.324Z — Explicit spreadsheet metadata mapping and blocking review
**Accepted implementation approach; CI pending:** Continue the existing bounded CSV/XLSX parser and shared review model. The user selects the task title column and may explicitly select two distinct columns for `requirement` and `notes`; do not infer semantics from headers or import optional metadata without selection. Exact documented requirement tokens Required/Optional/Unspecified/Yes/No/True/False/1/0 accepted (case-insensitive; blank=Unspecified). Invalid/ambiguous values and oversized notes are issues attributed to the original CSV line / XLSX row, not coerced or skipped. Refuse all-row acceptance until every issue is corrected; retain no automatic office save, macros, cloud transfer or historical checklist rewriting. **Tradeoff:** Applying the approved import replaces the current unsaved office editor draft; clear UI copy warns about this. Date/status/owner fields remain out of scope until separately typed and validated. Never infer legal document sufficiency from user-configured 'required' labels.


## ADR-015 — 2026-11-21T05:53:40.145Z — Office requirement/notes and non-destructive metadata migration
**Accepted implementation approach; CI pending:** Office template task rows gain three-state `requirement` (unspecified/required/optional) plus notes, both copied into the existing immutable per-transaction checklist snapshot. The unspecified default is necessary because older task titles do not establish legal or office-mandated requirements. Keep prior rows intact via idempotent SQLite ADD COLUMN migrations; preserve completion/link state, optimistic template revision checks, and title-only compatibility. UI edits typed metadata, not only titles. **Tradeoff:** status/due dates, CSV/XLSX metadata column mapping, multi-database transaction creation recovery and human Mac UX remain separate; don't generalize the workflow or claim legal sufficiency.

## ADR-009 — 2026-11-21T04:54:03.882Z — No owner Mac; CI-first development and deferred physical beta
**Accepted:** The owner has **no local macOS machine**. Regular ChatGPT + GitHub Actions macOS runners will handle source development, compilation, automated unit/integration tests, synthetic PDF fixtures, and feasible headless launch verification. Lack of an owner Mac **must not block** implementing M1–M5. ## ADR-010 — 2026-11-21T05:02:40.473Z — First PDF/document vertical slice
**Accepted:** Build a typed Swift actor `DocumentWorkspace` around local SQLite document/checklist metadata, immutable file copies by SHA-256, PDFKit source page extraction, Vision OCR fallback for pages without digital text, copy-only exports with hash verification, and manual document-to-task links. Do not create a cloud dependency or require Mac terminal use. Document import is user-selected and task execution is serializable in the actor. **Tradeoffs:** Initial document metadata resides in a separate SQLite file from transaction metadata, with transaction UUID scoping; batch progress and cancel are controlled by the GUI. OCR failures remain reviewable/unavailable rather than silently asserting success. Test user-visible Finder and OCR behavior later on external Mac; CI tests gate core correctness.

## ADR-012 — 2026-11-21T05:27:44.886Z — Versioned office template store with atomic transaction snapshot
**Accepted implementation approach:** Extend the existing document SQLite database via a dedicated OfficeTemplateStore rather than adding an external runtime or new storage engine. Each office has independent append-only template revisions per seller-side workflow. Existing checklist rows and source metadata are written together in one SQLite transaction. Manual or previously seeded transaction tasks are never overwritten. Snapshot rows preserve office display name/version even after later template edits. Saving edits requires an exact prior version to reject stale overwrites. **Tradeoff:** transaction metadata and document/checklist metadata remain in separate existing SQLite files; fully atomic transaction creation plus checklist initialization across both files is not yet provided. **Verification:** CI pending; real Mac usability untested.


## ADR-013 — 2026-11-21T05:32:20.683Z — CSV checklist import requires explicit mapping and human review
**Accepted:** Build a pure Swift/Fundation CSV parser (no cloud, spreadsheet macros, or new runtime dependency). Handle UTF-8 BOM and quoted fields; bound file size/row count; expose a user-selected task-description column. Never guess which column contains task titles, silently omit invalid rows, or replace office tasks on file selection. The read-only review sheet blocks acceptance on malformed/duplicate/invalid rows; successful review only stages names in an unsaved template draft. A separate user Save creates the next append-only revision using existing optimistic concurrency. **Tradeoff:** Only a task-title column is mapped in this initial CSV slice; statuses, requirements, mixed-workflow mapping and XLSX require subsequent work. **Verification:** macOS CI pending; real user Mac UI testing pending.


## ADR-014 — 2026-11-21T05:42:06.767Z — XLSX through bounded CoreXLSX and shared review workflow
**Accepted as implementation approach, CI pending:** Use CoreXLSX pinned to 0.14.2 (Apache-2.0) plus ZIPFoundation (MIT) and transitive XMLCoder (MIT). These are runtime libraries but need no network, API key or paid service. Limit source XLSX to 2 MiB, archive declared expanded bytes to 24 MiB, 200 ZIP entries, 20 worksheets, 2,000 data rows and 64 columns; reject workbook parsing errors, invalid shared-string references, formula/error cells. Preserve sparse row/column references. Human selects worksheet then task-description column; preview uses the existing CSV reviewer and applies only to an UNSAVED office template draft until separate Save. Do not evaluate formulas, execute macros, modify source, or silently discard invalid task rows. **Tradeoff:** bounded sizes are initial guardrails, not proof against all malicious OOXML; perform dependency SBOM/notice and ZIP/XML fuzzing before commercial release. Full metadata column mapping remains future work.
