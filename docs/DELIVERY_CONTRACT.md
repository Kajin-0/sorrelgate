# Sorrelgate — Outcome-based delivery contract

**Adopted working scope:** 2026-11-21. **Objective:** finish a trustworthy, commercially useful, local-first California **seller-side Accepted Offer** workflow without indefinite infrastructure churn. This document is the active execution/stop policy; `PRODUCT_SPECIFICATION.md` is the broader design reference, `ACCEPTANCE_TESTS.md` provides candidate release metrics, and the existing M0–M6 issues track implementation details. Amend this contract only on evidence of a material user or safety need.

## 0. Why this plan exists

Current verified `main` at adoption: `704e39c93947261305145dd5f944833df2c4a78a`, [macOS Actions #97](https://github.com/Kajin-0/sorrelgate/actions/runs/44910712360) **SUCCESS** with **51/51 XCTest** and native SwiftUI app build. Source-byte-preserving PDF import, synthetic Vision OCR, cancellation/retry, versioned office templates, reviewed CSV/XLSX imports and crash-safe transaction creation have substantial automated coverage. **No physical Mac user, genuine field-scan OCR, recovery of a whole backed-up workspace, functional recognition, reviewed timeline/drafts, or model-driven action execution has passed yet.**

The dominant remaining risk is not another 7-token OCR regression or one more operating-system error simulation: **the app has not delivered a whole accepted-offer transaction from paperwork to an evidence-backed, human-reviewed handoff**. Shift engineering effort from component hardening to connected outcomes.

## 1. One north-star workflow (freeze the scope)

On one supported Apple-silicon Mac, a nontechnical seller-side transaction coordinator:

1. Selects an office and creates an **Accepted Offer** transaction, with that office's exact versioned checklist and no duplicate/orphan tasks.
2. Imports **10–50 PDFs** (target stress: **50 PDFs / 300 pages**); originals are immutable and locally recoverable; digital and scanned pages retain extraction-method and source-page identity.
3. Receives **document labels, candidate important facts, missing-item and contradiction suggestions** with accurate original PDF/page citations and an explicit **Unknown / Needs Review** state. Detection never means legal validity or a verified signature.
4. Reviews and **confirms or rejects** consequential names, dates and amounts; tracks checklist progress and office tasks. Unconfirmed values remain placeholders.
5. Prepares a **reviewed timeline**, editable introductory/missing-document email drafts (never sent by Sorrelgate) and a **hash-verified package** with a useful manifest, unresolved issues and source references.
6. Quits/relaunches and sees exactly the same state; on a supported model-enabled Mac, optionally asks the agent to do equivalent low-risk steps through **the same typed, permissioned actions**, with visible approval gates and receipts.

**Out of scope until after the full workflow and pilot:** buyer-side workflows, multiple states, enterprise sync, cloud hosting, integrations with escrow/brokerage/MLS/DocuSign, external email sending, legal-rule engines, automated signature validation, payment infrastructure, unbounded UI embellishment, speculative agent tools, and any new OCR technology absent evidence that Apple Vision is inadequate. Existing listing-preparation templates remain supported, but do not expand them while the Accepted Offer vertical slice is incomplete.

### Evidence rules

- Every gate has an **artifact and source-of-truth test**; a successful `xcodebuild` is not evidence of a functional user journey. A unit test mocking an LLM is not evidence of an actual model run.
- Treat OCR token recall on generated large-font pages as a **regression test only**, not a real field-accuracy result; do not combine synthetic and real-scan statistics.
- If an evaluation has too few examples for a credible precision/F1 claim, record the actual sample sizes and uncertainty, leave the release metric **UNVERIFIED**, and proceed only with clearly labelled engineering checks.
- G1/G4 acceptance cannot be bypassed by model prose, incomplete citations or inferred fields. Use explicit `proposed`, `confirmed by user`, `rejected` and `unknown` semantics.
- Record all measurements with exact Git SHA, macOS/Swift/Xcode version, fixture mix, task definition, outcome and CI/pilot link.

## 3. Anti-churn policy: decisions, gates and exceptions

**One gate is active:** start G1. Work on G2–G5 only to remove a hard dependency or a confirmed P0/P1 safety risk. A PR must state the gate, the observable user outcome, the failing acceptance condition and the evidence that will close it.

**No speculative branches:** prohibit “polish”, performance tuning, parser rewrites, more mock data families, dependency swaps and UI architecture refactors unless a particular acceptance criterion is failing or a user pilot identifies a defect. A benchmark can be improved only if tied to real-world throughput, correctness or usability.

**A bounded iteration budget:** aim for **one complete vertical slice per PR**, with its direct tests and necessary schema/UI. After **two successive PRs that do not advance a gate**, pause coding and diagnose product assumptions, data scarcity or test design rather than starting a third speculative attempt. Fix genuine regressions immediately without resetting the objective.

**Definition of gate closure:** all listed pass criteria evidenced; remaining conditions marked one of **PASS / FAIL / BLOCKED (external)** with link. When passed, do not revisit without a measured regression, P0/P1 defect or documented TC feedback. “More robustness” without a failed target is **not a new task**.

**Scope change control:** adding a feature requires (a) which failing north-star step it fixes, (b) why existing capabilities cannot solve it, (c) how success is measured, and (d) which existing planned work is removed/deferred. The owner decides material budget, market, legal-risk and commercial distribution changes.

## 4. Immediate authorized work and global stopping points

**Next implementation deliverable: G1 vertical slice.** Introduce one evidence-proposal domain contract and persistence, extract one or two well-defined candidate fields from actual imported PDF page text, render its **Open original PDF — page N** link, allow **Confirm / Reject / Unknown**, and demonstrate a fresh/reopen test on two transactions. Extend only after that end-to-end path works. No AI inference dependency or checklist redesign at the outset.

**Engineering completion:** G1–G4 satisfy their internal code/test criteria and a reproducible beta package/handoff exists. If the external Mac or authorized field evaluation is unavailable, mark those gates **BLOCKED**, do not convert the gap into months of synthetic tests; stop feature work and seek the missing external evidence.

**Pilot completion:** G5 supervised Mac workflow and human usefulness checks pass with results recorded. **Commercial completion:** G5 independently confirms security, licensing and self-service signed/notarized installation after approved spend. Any P0/P1 privacy, data-loss, unsupported legal-completion claim or unauthorized action reopens the stop gate immediately.

**No additional MVP spending** without owner approval. Never put customer PDFs, names, signatures or licensed forms in public Git.
